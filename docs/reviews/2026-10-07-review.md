# Codypendent review — 2026-10-07

A whole-repository review at `76448fc` (v0.14.0): the open pull requests, the state of CI, a
read-through of the agent loop, the policy and sandbox layer, and the durability layer, and a
comparison with how the leading coding harnesses are built. Fixes landed on the branch
`claude/review-2026-10-07`; everything not fixed is listed in section 4 with the reason.

The companion document, [`2026-10-07-harness-landscape.md`](2026-10-07-harness-landscape.md),
holds the research on other harnesses and its sources.

## 1. The short version

- **`main` is red, and none of it is the code.** Every pull request opened since early October
  fails the same six CI jobs: a deprecation promoted to an error by the newest stable Rust, a
  TLS advisory in `rustls`, and `npm audit` highs in three JavaScript packages. All six are
  fixed on the branch.
- **The pull-request queue was 50 deep and mostly noise.** Twenty-eight were near-identical
  daily "Bolt" micro-optimisations; twenty-two were Dependabot. Two were merged, twenty-eight
  closed, and the rest are either folded into the branch or closed with a reason (section 2).
- **The harness is architecturally ahead of most of the field on durability and safety of
  file I/O, and behind on four things:** the model's own commands run without an OS sandbox,
  tool calls are replayed to the model as prose rather than as native tool messages, context
  management stops at "fold old results" with no summary tier, and nothing measures how good
  the agent actually is (section 5).
- **Twelve defects were fixed**, including three that were silently losing data or leaking it:
  an instruction-file symlink that could put `~/.aws/credentials` into the prompt, learned
  facts dropped under concurrent writes, and a repository-supplied symlink that could widen
  the file scope to the whole machine. Each fix carries a test that fails on the old code
  (section 3). One more security finding, in learned approval patterns, needs a product
  decision and is not changed (section 4).

## 4. Found and not fixed

Ranked. Each was checked against the code; none was changed because it needs a decision, a
migration, or more design than a review pass should invent.

1. **Learned approval patterns leave the argument tail free** (`policy/arity.rs`). One
   "always allow" of `rg <pattern>` learns `rg *`, which then auto-approves
   `rg --pre=<program>` and runs the program; `cargo build *` covers
   `--config build.rustc=…`. The fail-closed fix, refusing any trailing `-` token the pattern
   did not name, makes learned patterns useless for any command with flags. That trade-off is
   yours. A middle path is a short per-program list of flags that take a program or a config.
2. **The model's own commands are not OS-sandboxed.** Seatbelt and bubblewrap are wired only
   for plugin and hook guests; `shell.run` and the PTY tool rely on policy, an empty
   environment and a process group. This is the largest gap against Codex and Claude Code and
   would contain findings 1 and several others even when the policy layer is tricked. The
   sandbox crate already exists.
3. **Tool calls are replayed as prose in the user role** (`to_messages`): arguments clipped to
   200 characters, every tool result at user-level authority. It was done to avoid orphan tool
   messages, which is solvable by keeping the call id. Models trained on function calling lose
   the pairing, and repository content reads as the user speaking.
4. **No event retention.** Nothing deletes from `events` or about twenty-five other tables;
   `load_events` is an unpaginated per-session scan called at least three times per run, so the
   cost over a session is quadratic. `expire_due` scans the whole `approvals` table every
   thirty seconds with no usable index (a one-line partial index would fix that).
5. **Workflow restart can run a node's side effects twice** (`workflow/src/drive.rs`). A node
   that was running is reset and re-executed as a new run with no check for a started
   non-idempotent tool, whereas the agent layer refuses exactly that case.
6. **Language servers leak for preserved worktrees.** The fix for vanished roots is lazy and
   only fires when the directory is gone; a Build run that ends with unmerged work keeps its
   worktree and its server (hundreds of megabytes for rust-analyzer) until the daemon exits.
7. **Panic-safety of two supervisors.** The workflow drive and the remote-UI worker clean up
   inline rather than in `Drop`, so a panic leaves a run permanently "born cancelled" or burns
   a worker slot; `retry_from_node` has no run-state precondition.
8. **Smaller:** `edit_file` mixes line endings on CRLF files and returns no edited region;
   the compaction estimate omits the instruction text and over-counts `write_file` arguments;
   the 60-second idle timeout kills long prompt evaluation on local models; the empty child
   environment makes `npm test` unrunnable under nvm; cancel races a detached blocking write;
   `artifact.read` cannot page; a corrupt `failure = "block"` hook is quarantined rather than
   treated as a block; the env deny-list is still a deny-list (`GIT_ASKPASS`,
   `RIPGREP_CONFIG_PATH` and others are not on it).

## 5. How Codypendent compares with the field

Compared with Claude Code, Codex CLI, Aider, OpenHands, SWE-agent, Cline/Roo, Cursor, Gemini
CLI, Amp and the rest, as surveyed in the companion document. The Codypendent column comes from
reading the code at `76448fc`, not from running it against a benchmark, because there is no
benchmark to run (last row).

| Area | What the best do | Codypendent | Verdict |
|---|---|---|---|
| Process model | A core engine behind a protocol: Codex app-server, OpenCode, OpenHands agent-server, Claude Agent SDK | Persistent daemon, typed protocol, event-sourced SQLite ledger, crash recovery, per-user isolation by `SO_PEERCRED` | **Ahead** on durability; only Codex comes close |
| Core loop | One plain model → tools → results loop; planning as a mode | Same, with step and wall-clock caps, a repeated-call guard and safe-point steering; plan, review and ask modes | At par |
| Edit tool | Exact-match replacement with uniqueness checks and normalised fallbacks (Claude Code, OpenCode, Roo) | Ten-stage cascade ported from OpenCode, atomic descriptor-relative writes, and now refuses ambiguous fuzzy matches | At par; **gaps:** no echo of the edited region, no stale-file check, CRLF |
| Feedback after edits | Lint, LSP or tests after each edit (SWE-agent, Aider, OpenCode, Cursor) | LSP diagnostics fed back into the edit result | At par or ahead |
| Tool-call transcript | Native tool-use and tool-result messages | Prose replay in the user role | **Behind** (finding 3) |
| Tool surface | A small core set plus deferred loading of the long tail (Claude Code's tool search saves about 85% of schema tokens) | 42 tools, narrowed by retrieval once per run; the always-on floor omits `git.diff`, `repository.test`, `artifact.read`; no glob or directory listing | Different, and risky at the floor |
| Context management | Layered: cap tool output, clear old results, summarise (Claude Code has five layers); OpenHands condenses at read time; Amp abandoned summaries for handoff | Salient head/tail views with artifact spill, then folding of old results to artifact-backed stubs at 80% of the window | **Behind** on tiers, strong on spill |
| Repository understanding | Aider's PageRank repo map; Cursor's semantic index | Tree-sitter code graph, hybrid retrieval, a repo map and cited memories assembled at run start | At par; unmeasured |
| Instruction files | `AGENTS.md` is the cross-tool standard | `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.cursorrules` and more, hierarchical | At par, and now contained and budgeted |
| Sandbox | OS sandbox for the model's own commands with an allow-listed egress proxy (Codex, Claude Code) | Only for plugins and hooks | **Behind** (finding 2) |
| Approvals | A second model approves routine actions (Claude Code auto mode, Codex Guardian); the motivation is that people approve about 93% of prompts | Durable, auditable approvals with arity-learned patterns; deny wins | Richer audit, no reviewer model |
| Sub-agents | Summary-returning context firewalls (Claude Code `Agent`, Codex, Amp) | Durable multi-model councils and declarative workflows; no lightweight delegate | **Behind** for the cheap case, ahead for the heavy one |
| Hooks, skills, MCP, ACP | Claude Code has 27 hook events | Hooks run inside the sandbox and are re-evaluated by policy; `SKILL.md` compatible; MCP client; ACP client and server | At par or ahead |
| Prompt caching | Provider-side caching of tools and instructions | None | **Behind** |
| Measurement | Terminal-Bench, SWE-bench; same model moves several points between scaffolds | A 13-case corpus scored by a deterministic stub, which cannot detect a prompt or skill regression | **Behind** |

Three observations from the research that bear directly on this codebase:

- **The model, not the scaffold, is increasingly the product.** mini-SWE-agent reports over 74%
  on SWE-bench Verified with bash only and a linear history, and its authors say a year of model
  progress made most specialised tools unnecessary. A 42-tool surface is a bet against that.
  Only measurement can tell whether it pays.
- **Compaction is the active research front.** Amp dropped summarisation for handoff; recent
  papers find that never paraphrasing (truncate and clear only) beats summarising, and that a
  summary can erase safety constraints. A summary tier added here should be tested before it is
  trusted, which again needs measurement.
- **Approval fatigue is the reason classifier-approved autonomy became the default in 2026.**
  The durable approval model here is a better audit trail than either leader's, and a reviewer
  model on top of it would give the autonomy without losing that.

    guard on workflow restart; evict language servers when a worktree is released.

## 7. Method and limits

- **What was run:** `cargo check`, `clippy -D warnings`, `fmt`, and the full workspace test
  suite on the final tree (results in section 8); `npm ci`, each package's check and
  `npm audit --audit-level=high` for all eight JavaScript packages; the three documentation
  gates.
- **How findings were handled:** three read-only reviews (runtime, policy and sandbox,
  durability) produced candidates. Each one acted on was re-read in the code first, the fix was
  written with a test, and the test was run against the old code where that was practical.
  Several candidates were already fixed and are not repeated; `improvement_plan/` is updated
  with their status.
- **Not verified here:**
  - The desktop's Tauri crate could not be linked locally (no `webkit2gtk`), so its changes
    (the `try_update` rename, `base64` 0.23, lockfile updates) rest on CI. Its formatting was
    checked.
  - No live provider call was made. The Anthropic tool-name rule was read from its current
    documentation; OpenAI's was not re-fetched (the page returned 403) and rests on the review
    and on my own knowledge of that API.
  - Nothing was run on macOS.
  - The sandbox, workflow and durability findings in section 4 were confirmed by reading, not
    by reproducing, apart from those with tests in section 3.
  - A fourth review, of the TypeScript packages, stopped when the account hit its spend limit.
    Its partial results (every suite passing, every audit failing, which bumps work) were
    reused and then re-verified by running the fixes.
- **Benchmark figures in the companion document are secondary-source numbers** and are
  flagged as such there.
